# 0005. How v0.1 is distributed

Status: **accepted**, 12 November 2026, by Joe at the REL.release.plan pause: OD-23, OD-24, OD-26 and OD-29 as
proposed, and OD-25 with numbers-only quoting. The plate's pattern, frame range and colour space are still to be
supplied, so `REL.gate.plate` stays closed until they are.

## Decision

**Ship a builder and an installer, never a built asset. Joe's plate proves it; it does not enter git.**

| | Rule |
| --- | --- |
| What the repository ships | `houdini/build/build_hdas.py`, `tools/install.py`, the worker and the asset's sources. No `.hda` is committed or attached to the release, because an Indie build is limited commercial (FACTS P7); `houdini/otls/` stays git-ignored (M3, OD-15) |
| How a user installs | One file, `install.py`, run once: it builds the worker environment, writes `local.toml`, runs the self-test, builds the asset **under the user's own licence** when the stamp differs from the tree, and writes exactly one package file into the folder desktop Houdini reads (OD-24) |
| What the GitHub pre-release carries | `install.py` only, and that copy clones the `v0.1.0` **tag**, never `main`, so a user on v0.1.0 keeps getting v0.1.0 (OD-23) |
| The candidate branch | `release/v0.1.0`, committed with Joe's consent; he merges and tags it himself, outside the session |
| The plate | An EXR sequence of at most 4K and 100 frames, kept outside the repository; it is baked through M3's `bake_timing.py` unchanged, so the artist's path is what is proved. Only numbers are committed: pixels and paths never enter a tracked file (OD-25) |
| Line endings | No `.gitattributes` before v0.1. The lock and the build stamp hash with line endings normalised, and a fresh clone proves it (OD-26) |
| The licence | v0.1 ships with no licence file, and the README says so; default copyright applies. Decision 0001's licence item stays open; only its release-gate box is ticked (OD-29) |

## Why

- **A built asset cannot be redistributed honestly.** An Indie-built `.hda` is limited commercial, so the only clean
  distribution is the builder plus a licence the user holds.
- **The tag pin is the difference between a release and a moving target.** A downloaded `install.py` that clones `main`
  would install whatever main holds at the moment it runs.
- **The plate is the only evidence that the product works on real footage.** It belongs in the evidence, not in the
  repository: numbers in `docs/facts/rel_plate_summary.json`, nothing else.
- **Normalised hashing already exists.** The lock and the build stamp both normalise line endings, so a CRLF checkout is
  proved by the fresh clone rather than pinned by a new file.

## What this decision does not cover

- Which licence, if any, the project takes later. That is 0001's open item and stays open (OD-29).
- How the asset is built at a *studio* rather than by one artist; v0.1 assumes one user, one licence.
